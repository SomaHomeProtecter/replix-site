# docs — HP-87 공개 랜딩 페이지

`replix.tv` 에 들어갈 랜딩 페이지 소스다. 폴더 이름이 `docs`인 이유는 이게 GitHub
Pages가 지원하는 두 소스 위치 중 하나이기 때문이다(레포 루트 `/` 또는 `/docs`) —
**여기가 곧 배포물**이라 별도 승격·복사 단계가 없다.

**2026-08-06부터 `replix.tv`가 이 폴더를 실제로 서빙한다** — `main` push가 곧 배포다.
문구는 여전히 초안이다(담당자 직접 작성, 확정 전 override로 먼저 공개됨). 고칠 땐
로컬(`python3 -m http.server`)에서 먼저 확인하고, `main`에 머지하면 `replix.tv`가
갱신된다(레포 루트 README '배포 구조' 참조).

## 열어 보기

```bash
python3 -m http.server 8000     # http://localhost:8000
```

⚠️ **`file://` 로 직접 열면 동작하지 않는다.** JS 를 ES 모듈로 쪼갠 뒤부터
브라우저가 `file://` 의 모듈 로딩을 CORS 로 막기 때문이다. 반드시 서버로 연다.

## 구조

한 파일에 CSS·JS 를 모두 담던 방식(2,556줄)에서 2026-08-05 에 쪼갰다.
번들러는 쓰지 않는다 — 브라우저가 그대로 읽는 파일이 곧 배포물이라 빌드 단계가
없고, nginx 도 이 디렉토리를 그대로 서빙한다.

`js/` 에 파일 하나를 더하고 `main.js` 에 한 줄 추가하면 된다.

## 고칠 때 알아 둘 것

- **배포 뒤 10분은 새 HTML 과 옛 JS·CSS 가 섞일 수 있다** — GitHub Pages 는 모든 파일에 `cache-control: max-age=600` 을 붙인다. 배포 전에
  페이지를 연 브라우저는 새로고침해도 HTML 만 새로 받고 JS·CSS 는 10분까지 캐시에서 쓴다. 2026-10-17 새 첫 화면이 들어온 직후 옛 `main.js`
  (top.js 를 부르지 않던 판)가 섞여 첫 화면에 영상만 남았다(HP-666). 그래서 첫 화면 연출 `js/top.js` 는 `index.html` 이 직접 부르고
  `main.js` 는 부르지 않으며(부르면 top.js 하나가 실패할 때 main.js 묶음 전체가 멈춘다), 연출이 2.5초 안에 시작 표식(`hx-live`)을 달지 않으면
  `<head>` 안전장치가 패널이 열린 정지 화면으로 둔다(`scripts/test-hero.mjs`). 배포 직후 확인은 강력 새로고침(`Cmd+Shift+R`)으로 한다.
- **문구는 전부 초안이다.** 최종 문구는 담당자가 직접 작성한다(2026-07-13 팀 결정).
  첫 화면 제목은 광고와 같은 말 `친구랑 넷플릭스, 이제 진짜 같이`다(HP-662, 2026-10-16). 히트맵 `같은 장면에서, 시간이 달라도
  우리는 만난다` → 마지막 `혼자서도 같이 보는 즐거움, Replix에서` 는 서로 변주 관계라 하나를 고치면 나머지도 함께 본다.
- **검색 노출(HP-645)** — 첫 화면 `<title>`·설명·og 는 같은 글을 쓰고, 구조화 데이터(WebSite·SoftwareApplication)가 `<head>` 에 있다.
  네이버 웹마스터 가이드는 제목·설명에서 같은 키워드를 두 번 넘게 쓰거나 노출을 노려 자주 바꾸면 불이익을 준다고 적으니, 고칠 때 한 번에 정해서 고친다.
  검색에 보일 페이지를 새로 만들면 `sitemap.xml` 에 한 줄을 더하고 `<link rel="canonical">` 을 단다. 색인에서 뺄 페이지는
  `robots.txt` 로 막지 말고 `noindex` 를 단다(막으면 로봇이 그 태그를 못 읽는다).
- **설치 CTA 는 세 곳(내비·첫 화면·마지막)**이고 모두 웹 스토어로 간다(`utm_medium` = `nav`·`hero`·`close`, 계측 `data-cta` 도 같은 값).
- **휴대폰 기기에선 설치 버튼이 웹 스토어로 가지 않는다**(HP-477). `js/install-guide.js` 가 익스텐션을 깔 수 없는
  기기(안드로이드·iPhone·iPad)에서 `[data-cta]` 클릭을 가로채 'PC 크롬에서 써요' 시트(링크 복사·공유·웹 스토어)를 띄우고,
  `<html>` 에 `rx-mobile-device` 를 달아 `.rx-mobile-only`/`.rx-pc-only` 문구를 바꿔 끼운다. 판정은 화면 폭이 아니라 기기다.
  첫 화면·마지막 설치 버튼은 휴대폰 기기면 'PC로 설치 링크 보내기'가 된다. 표식은 `<head>` 의 인라인 스크립트가 첫 그림 전에 단다 —
  모듈 스크립트만 기다리면 첫 그림에 PC 문구가 잠깐 보인다(HP-662). 그 판정은 `isMobileDevice` 와 같아야 한다(`scripts/test-install-guide.mjs` 가 대조).
  작품 탐색도 같은 파일을 런타임에 붙인다. 초대 페이지(`invite/index.html`)와 디스코드 연결 페이지(`together/index.html`, HP-497)는
  단일 파일이라 판정 사본을 두며, 휴대폰이면 링크 복사를 보여 준다 — 판정을 고치면 셋 다(검사: `node scripts/test-install-guide.mjs`).
  두 페이지의 PC 경로(2.5초 대기 후 설치 안내, 초대는 방 요약까지)는 `node scripts/test-invite.mjs` 가 지킨다.
  헤더는 760px 이하에서 설치 버튼을 숨기고 '작품 탐색'만 남긴다.
- **계측(Amplitude)은 `js/analytics.js` 한 곳이다**(HP-415). 이벤트를 추가·변경하려면
  **`analytics/tracking-plan.md` 부터** 고친다 — 코드에만 있고 문서에 없는 이벤트는 버그다.
  설치 CTA 는 `data-cta="…"` 속성만 붙이면 자동 계측되고(세 곳 = `nav`·`hero`·`close`), 그 밖의 링크는
  `data-link="<target>" data-link-loc="nav|footer"` 로 버튼마다 구분해 센다(HP-437 — **랜딩에 `<a>` 를 새로 붙이면
  둘 중 하나를 반드시 단다**, 안 달면 검사가 깨진다. 값은 `analytics.js` `LINK_TARGETS` 의 열거값만). 동의 배너·SDK
  로드·철회는 그 파일이 맡는다. **세션 리플레이는 랜딩·작품 탐색, 운영은 2026-10-01 부터**(HP-457, 트래킹 플랜 §9) —
  누구를 찍나는 `replayFor()`: [허용]이면 어디서나, **한국 시간대 랜딩은 2026-10-10 부터 미선택이어도**(`REPLAY_OPTOUT_FROM`),
  작품 탐색·해외 미선택과 거부는 안 찍는다. 시행일을 옮기려면 `analytics.js REPLAY_FROM`/`REPLAY_OPTOUT_FROM` 과 `privacy.html`
  시행일을 같이 고친다(검사가 둘을 대조한다).
  랜딩·작품 탐색에 입력 필드나 이용자가 쓴 글·이름이 들어가면 그 요소에 `amp-mask`(글자 가림)·`amp-block`(통째로 가림)을 단다.
  **Google Analytics 도 같은 파일이 붙인다, 운영은 2026-10-01 부터**(HP-465, 트래킹 플랜 §10) — `gtag` 정적 태그를
  HTML 에 넣지 않는다(동의 전 수집이 된다). 시행일은 `GA_FROM` 과 `privacy.html` 을 같이 고친다. GA 관리의 **향상된 측정은 꺼 둔다**.
  **한국 시간대는 랜딩·작품 탐색 모두 2026-10-01 부터 옵트아웃**(HP-466, 트래킹 플랜 §11) — 미선택이어도 이벤트를 보내고 배너는 '안내 + 거부'.
  해외는 허용 뒤에만(리플레이는 위). ⚠️ 웹 이벤트에 회원 식별값·IP 를 싣지 않는다 — 싣는 순간 옵트아웃 근거가 무너진다.
  검사: `node scripts/test-analytics.mjs`. `/invite`·`/together` 는 계측하지 않는다(토큰).
  **로컬(`localhost`·`127.0.0.1`·사설망)에서는 GA·Amplitude 로 보내지 않는다**(HP-615) — 실제 전송을 봐야 하면
  `?replix_analytics_debug=1` 로 그 브라우저에 표시를 남긴다(`=0` 해제). 팀원 브라우저는 운영에서 `?replix_internal=1` 로 한 번 들어가
  `traffic_type=internal` 표시를 남긴다(버리지 않고 표시만, 트래킹 플랜 §5). **웹 스토어 링크에는 `utm_source=replix.tv&utm_medium=<위치>`**
  를 붙인다(트래킹 플랜 §12 — 빠지면 검사가 깨진다).
- **화면 안 UI 는 익스텐션의 실제 구조·색을 옮긴 것**이다. `--accent: #e50914` 등
  토큰이 `Replix-extension/styles.css` 와 짝이므로 임의로 바꾸면 설치 전후가
  다른 제품으로 보인다.
- **없는 기능을 그리지 않는다.** 익스텐션에 없는 UI(정렬 셀렉터, 회차 드롭다운 등)는
  의도적으로 뺐다.
- **이미지는 전부 실제 작품 실물 캡처다**(2026-08-03 조현빈 결정). 생성 이미지는
  쓰지 않는다. 예외는 첫 화면 영상으로, 가상의 작품 '밤의 정원'을 Pexels 무료 영상으로 만들었다(HP-662, `notes/hero-scene.md`).
- **히어로 플레이어·시네마 섹션의 채팅·시청 인원은 시뮬레이션(예시)이다** — 푸터에
  밝혀 두었다. 반면 **히어로 통계 띠와 '리플릭스에서 많이 본 작품' 섹션은 실데이터다**
  (`/api/v1/public-stats`, 2026-08-05). 데이터가 하한선에 못 미치면 통계 띠는
  숨고, '많이 본 작품'은 모자란 자리에 "데이터 없음"을 보여준다 — 둘 다 대체 콘텐츠로
  메우지 않는다. 상세는 아래 '실데이터 연동' 참조.
- **`meta robots noindex` 는 이미 제거됐다**(2026-08-06, 실공개와 함께) — `index.html`에
  다시 넣지 말 것.

### 시뮬레이션을 만지는 자리

| 상수 | 파일 | 역할 |
| --- | --- | --- |
| `LIVE` | `js/hero.js` | 히어로 라이브 채팅의 도착 시각과 내용 |

| `CHAT_POOL` / `ARCHIVE` | `js/scenes.js` | 회차에 쌓인 반응. 밀도 함수로 생성하며 시드 고정 |

| `--y` / `--dur` / `--wait` | `index.html` `#rooms` `.rm-dm`(이전 랜딩 `landing-v1`) | 함께 보는 방식 공개 채팅 카드의 탄막 줄 높이·지나가는 시간·시작 지연. CSS 애니메이션이다(`css/rooms.css`) — `js/rooms.js` 는 화면 밖에서 멈추기만 한다. HP-664 로 `#rooms` 를 빼 지금은 쓰이지 않는다 |

  되살릴 때는 대개 마크업만 가져오면 된다.
- 되살리거나 A/B 시험에 쓰기 전에 볼 것: ① `#intro`·`#works` 의 작품 사진 5장은 출처를 모르는 실제 작품 장면이다(워크스페이스 CLAUDE.md §7) —

  계측 표면(`/`·작품 탐색) 밖이라 배너·옵트아웃 규칙이 맞지 않는다.

## 실데이터 연동 (HP-87, 2026-08-05)

`js/publicStats.js`가 `GET /api/v1/public-stats`(BE `domain/live` 패키지)를 한 번만
불러 히어로 통계 띠(`js/stats.js`)와 '많이 본 작품'(`js/chart.js`)이 나눠 쓴다.

운영 문서의 `api-base`는 PROD API(`https://api.replix.tv`)를 가리킨다. '많이 본 작품' 섹션이
숨김 상태이면 `main.js`는 `chart.js`를 import하지 않으며, API 응답의 `mostWatched` 최종 차단은
BE의 `public.most_watched.enabled`가 담당한다(HP-358). 전역 ON은 숨긴 섹션을 자동 재노출하지 않는다.
API 주소는 `<meta name="api-base">`(`index.html`) 한 곳에서만 정한다.

정적 홍보 이미지처럼 이미 배포된 파일 URL은 런타임 응답으로 회수할 수 없다. 제거가 필요하면 원본 삭제,
사이트 재배포, CDN 캐시 무효화와 직접 URL 404 확인을 별도 런북으로 수행한다.

- **히어로 통계 띠**: 지금 보고 있는 사람 5명 미만이면 `#strip` 전체를 숨긴다
  (대체 문구를 넣지 않는다 — 페이지 다른 곳이 이미 그 말을 하고 있다는 판단).
- **많이 본 작품**: BE가 누적 감상 시간(presence 하트비트 간격 누적) 기준으로
  이미 랭킹까지 매겨 최대 5개를 준다. 각 작품엔 저장된 채팅 중 무작위로 고른 실제
  인용이 붙을 수 있다(없으면 인용 없이 카드만). **회차 썸네일·줄거리도 함께 온다**
  (HP-309, 2026-08-08) — 그 작품에서 가장 많이 본 회차의 것이며, 익스텐션이 재생 시점에
  수집해 서버가 저장해 둔 값이라 **아무도 안 본 작품은 비어 있다**. 그때 카드는
  종전처럼 작품 고유색 색면으로 떨어진다(오류가 아니라 폴백이다). **5개보다 데이터가 적으면 남는
  칸은 "데이터 없음"이다** — 넷플릭스 목록 등으로 채우지 않는다. BE가 죽거나
  응답이 늦어도 `fetchJson`이 빈 배열을 주므로 전부 "데이터 없음"으로 안전하게
  떨어진다(빈 화면이 스치는 구간이 없다).

⚠️ **CSS `display` 선언이 `[hidden]` 속성을 이긴다** — 클래스 셀렉터로 `display`를
정해 둔 요소는 author stylesheet가 UA `[hidden]{display:none}`과 동점
specificity라 뒤에 로드된 쪽이 이긴다. 이런 요소를 스크립트로 숨길 땐
`el.hidden=true`가 아니라 `el.style.display="none"`으로 직접 끌 것.
