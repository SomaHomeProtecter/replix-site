# catalog — HP-124 작품 탐색 페이지 (`replix.tv/catalog/`)

> 이름: 화면은 **작품 탐색**(메뉴 라벨 '작품'), 내부 명칭은 **catalog**. 2026-09-07 조현빈 결정으로 '큐레이션'에서
> 바꿨다 — 큐레이션은 누군가 골라 편성한다는 뜻인데 이 페이지는 편성·개인화·지수 없이 실제 시청·채팅 기록을
> 작품 → 회차 → 순간으로 펼치는 참조 카탈로그(왓챠피디아와 같은 성격)라서다. 옛 경로 `/curation/`은 폐기했다.

작품 탐색 페이지의 **소스**다. 배포물은 `docs/catalog/index.html` 한 장이며, 이 앱을 빌드해 그 파일을
갱신하고 함께 커밋한다(레포 README '배포 구조' 예외 항목). 2026-09-05 초안(`draft-curation`, 미커밋)에서
실제 표면으로 승격했고, 랜딩(`/`)과 같은 도메인에 두고 서로 오갈 수 있게 내비를 이었다.

## 고치고 배포하기

```bash
cd app
npm install
npm run dev            # 개발 서버(대상 API 는 index.html 의 <meta name="api-base">)
npm run preview:file   # 빌드 → ../../docs/catalog/index.html 갱신 (이걸 커밋한다)
npm run shot           # 빌드 후 데스크톱·모바일 스크린샷을 ../shots 에 저장
```

`docs/catalog/index.html` 은 file:// 로도 열린다(자기완결). 라우트는 `#/`(홈), `#/title/{contentId}[/ep/{episodeId}]`(상세).

## 구조

| 경로 | 내용 |

| `app/src/pages/Title.tsx` | 작품 상세 — 히어로, 회차, 순간, 대표 채팅, 함께 본 작품 |
| `app/src/components/primitives.tsx` | 파형, 반응 유형 막대, 포스터 자리표시, 진입 연출 |

두 화면은 해시 라우트로 한 파일 안에 들어 있다. 홈은 `preview.html`, 상세는

`file://` 에서 CORS 로 막혀 서버 없이 열리지 않기 때문이다. 코드와 스타일은 전부
인라인이지만 **포스터 이미지만 예외로 TMDB CDN 을 참조한다** — 레포의
"외부 리소스 0" 규칙과 어긋나는 유일한 지점이고, 아래 '고칠 때 알아 둘 것' 참조.

## 2026-09-03 개편에서 바뀐 것

**레이아웃은 그대로 두었다.** 포스터 12칸 격자, 순간 카드 다섯 장, 가로 카드
레일, 예능·드라마 두 줄, 상세의 회차 목록과 순간 목록은 원 시안의 구조와
순서를 유지한다. 바꾼 것은 테마와 마감이다.

- **다크에서 라이트로.** 토큰을 `docs/css/tokens.css` 의 라이트 값
  (`--warm #faf9f9`, `--ink #101016`, `--accent #e50914`)에 맞췄다. 이제 랜딩과
  같은 표면 위에 있다. 원 시안에서 다크 그러데이션 띠였던 빌보드와 상세
  히어로는 흰 면과 아래쪽 실선으로 바꿨다 — 라이트 페이지에서 한 섹션만
  어두우면 스크롤 도중 다른 사이트로 넘어간 것처럼 읽힌다.
- **반응 3색을 라이트용으로 다시 계산했다.** (2026-09-05 이후 화면에서 뺌, 아래 참조) 기존 `#c98500` `#3987e5` `#d55181`
  은 **다크 표면 기준** 검증값이라 라이트 배경에서 대비가 2.75~3.94 로 미달했다.
  새 값은 `#a66a00`(웃음) `#1f5fb8`(놀람) `#b23a66`(감동)이고, 세 라이트 배경
  (`#faf9f9` `#ffffff` `#f2f2f5`)에서 4.01~6.20 이다. 세 색끼리의 대비는
  1.09~1.38 로 여전히 낮으므로 **어느 표시에서든 이름과 %를 같이 붙인다** —
  색맹 대응은 색이 아니라 이 라벨이 보장한다. (아래 '미결' 참조)
- **포스터 자리표시를 활자 판으로 바꿨다.** 이전에는 작품마다 다른 색
  그러데이션이라 21개의 서로 다른 색면이 화면을 지배했고, 자리표시가 아니라
  '가짜 아트'로 읽혔다. 그렇다고 빈 회색 사각형만 두면 서른여섯 칸이 전부
  같은 빈 칸이 되어 화면이 완성된 것이 아니라 로딩 중인 것처럼 보인다.
  지금은 종이 질감 위에 **작품명을 직접 앉힌다** — 칸마다 글자 수와 줄바꿈이
  달라 각각이 구분되고, 이미지가 없다는 사실도 숨기지 않는다. 글자 크기는
  타일 너비에 비례시킨다(컨테이너 단위 `cqw`). **2026-09-04부터 이 활자 판은
  기본 표시가 아니라 폴백이다** — 위에 TMDB 포스터가 덮이고, 매칭 실패·로드
  실패·오프라인일 때만 드러난다.
- **트랙 있는 진행 막대를 없앴다.** 지수 막대에 회색 배경 트랙이 있으면
  대시보드 진행바로 읽히고, 순위와 레일에 서른 개가 깔리면 화면이 눈금자가
  된다. 지금은 트랙 없이 선 하나의 길이만 남겼다.
- **테두리 상자의 반복을 줄였다.** 순간 카드 다섯 장은 각각 테두리를 두르는
  대신 판 하나에 올리고 세로 실선으로 갈랐고, 상세의 회차 일곱 줄과 순간
  다섯 줄도 각각의 상자가 아니라 판 하나 안의 줄이 되었다. 인기 순간 카드와
  대표 채팅은 테두리 대신 채움으로 만들었다 — 화면의 거의 모든 것이 흰 면 +
  1px 테두리이면 다른 종류의 요소들이 전부 한 종류의 상자로 보인다.
- **한 카드 안에서 같은 값이 두 번 나오지 않게 했다.** 순간 카드에 우상단
  대표 반응 칩과 하단 3색 막대가 함께 있어 같은 수치가 두 번 나왔다. 막대만
  남겼다. 반복되던 "익명 시청자" 라벨과 카드 안의 작은 점축도 지웠다.
- **라벨 없는 반응 막대는 붙여서 하나의 비율 막대로 만들었다.** 목록 행처럼
  라벨을 붙일 수 없는 자리에서 세 토막을 띄워 두면 짧은 선 세 개가 떠 있는
  꼴이라 비율이 아니라 장식으로 읽힌다.
- **강조색은 1위와 선택된 항목에만 쓴다.** 순위 열두 칸을 전부 빨간 막대로
  칠하면 순위 차이가 아니라 빨간 줄무늬가 되어 정작 1위가 묻힌다.
- **가운뎃점(`·`)을 화면에서 뺐다.** `22기 8화 · 62:30 · 뜨거운 순간 4` 처럼
  한 줄에 여러 개 쓰면 구분자가 아니라 무늬가 된다. 세로 실선(`Rule`)과
  간격으로 나눈다.
- **눈썹 라벨을 뺐다.** 원 시안의 `오늘 1위 회차`(mono 대문자 `letter-spacing:.18em`)
  처럼 제목 위에 얹는 넓은 자간 소문자 라벨은 모든 섹션에 붙으면 같은 리듬이
  반복된다. 지금은 제목과 같은 줄의 작은 칩 하나로 줄였다.
- **상태 점은 라이브 인원 하나만 남겼다.** 반응 유형 범례 앞의 색점 등
  장식용 점은 뺐다 — 막대와 라벨이 이미 같은 일을 한다.
- **상세의 회차 목록에서 줄마다 그은 실선을 없앴다.** 목록 구조는 그대로 두고
  줄 사이를 띄워 각 줄을 카드로 만들었다. 순간 시각은 점 아래 제자리에
  붙였다 — 한 줄에 몰아 쓰면 어느 점이 몇 분인지 알 수 없어 축의 의미가 사라진다.
- **섹션 여백과 제목 크기는 원 시안 값을 지켰다**(세로 36px, 좌우 48px, 제목
  19px). 이 값을 랜딩식(64~80px, 26~30px)으로 키우면 같은 내용이 카탈로그가
  아니라 소개 페이지처럼 읽힌다. 실제로 한 번 그렇게 만들었다가 되돌렸다.

## 2026-09-05 개편 (impeccable critique 반영)

`/impeccable critique` 결과(휴리스틱 20/40, 검출기 0건)에서 팀 판단 없이 고칠 수
있는 것을 반영했다. 팀 판단이 필요한 것은 아래 '미결'에 남겼다.

- **순간에서 넷플릭스로 가는 길을 붙였다.** 빌보드·뜨거운 순간·상세 순간 목록의
  CTA 가 `netflixWatchUrl(id, sec)` (`https://www.netflix.com/watch/{id}?t={초}`)
  로 새 탭에서 열린다. 사용자의 브라우저가 이동하는 것이지 서버가 넷플릭스에
  요청을 보내는 것이 아니므로 규칙 §7 경계 안이다. **시안은 작품 ID 로 대신하고
  있다** — 실제로는 회차 ID 가 들어가야 한다.
- **'이 회차의 뜨거운 순간'은 포스터 + 트랙리스트다.** 쓸 수 있는 이미지가
  작품 포스터뿐이므로(회차 썸네일·장면 이미지 없음 — 조현빈 결정, 2026-09-05
  재확인) 순간마다 이미지를 요구하는 구성은 전부 배제한다. 포스터 하나를
  왼쪽에 세우고 순간 다섯 개를 곡 목록처럼 오른쪽에 놓는다(앨범 커버와
  트랙리스트의 관계). 줄마다 번호·시각·이름·인용·대표 반응·지수가 표처럼
  정렬되고, 1위 줄만 연한 강조 배경과 강조색. 번호 자리에 마우스를 올리면
  재생 아이콘으로 바뀌고 줄을 누르면 그 시각부터 넷플릭스에서 연다.
  앞서 같은 카드 5장 → '1위 패널+목록' → 세로 타임라인 → 가로 시간축
  (`archive/hot-moments-time-axis/`, 랜딩 재사용 후보) → 포스터 크롭 장면
  타일을 차례로 시도했고, 각각 생성물 격자·대시보드·빈 목록·랜딩 느낌·
  가짜 썸네일로 판정돼 되돌렸다.
- **모바일 빌보드 파형은 막대 48개(`WAVE_SM`)다.** 120개를 350px 에 넣으면
  1px 미만이 되어 봉우리가 뭉개진다.
- **상세 회차 목록은 회차순이 기본**이고 '지수순' 토글이 있다.
- **계정을 전제하는 요소를 뺐다.** 헤더 아바타, '새 회차 알림', '함께 볼 사람
  찾기'. 대신 '확장 설치' 하나만 둔다(개인화 없음 결정과 맞춤).
- **대표 채팅이 순간별로 바뀐다**(`CHATS_BY_MOMENT`). 상세 순간 목록의 라벨 없는
  3색 막대는 가장 큰 반응 하나의 이름+% 로 바꿨다.
- **지수 정의 한 줄**(`SCORE_DEFINITION`)을 빌보드 툴팁과 상세 히어로에 둔다.
- **시안 면책은 최상단 띠**(`DraftBanner`)로 올렸다. 푸터의 TMDB 고지와 섞이면
  둘 다 읽히지 않는다.
- **반응 유형(웃음·놀람·감동)은 화면에서 전부 뺐다(조현빈, 2026-09-05).** 실제
  서비스가 다루지 않는 데이터다. `data.ts`의 `reaction` 필드와 `ReactionBar`는
  남아 있지만 어디서도 그리지 않는다 — 서버 스펙에서도 빼야 한다. 그 자리는
  **채팅**이 채운다: 회차 카드마다 그 회차의 채팅 두어 줄, 히어로에 가장 공감한
  채팅 한 줄, 순간 목록의 인용. 이 서비스의 자산은 채팅이므로 상세 페이지의
  밀도는 채팅으로 만든다.
- **회차 섹션은 카드 격자다.** 회차 한 줄이 가로 화면 전체를 차지하면 훑기에
  나쁘고 지수 선의 뜻도 안 보였다. 카드(4열)에 회차·지수·반응이 몰린 순간·채팅
  3줄·순간 점 축을 담는다. 지수 선이 있는 목록(홈 트랙리스트·상세 순간 목록)에는
  열 이름 줄을 두어 "선 길이가 지수"임을 한 번 밝힌다.
- **상세의 '순간'은 마스터-디테일이다(2026-09-05 저녁).** 왼쪽 목록에서 순간을
  고르면 오른쪽에 그때의 채팅 로그와 "그 시각부터 보기" 버튼이 뜬다. 별도였던
  '대표 채팅' 섹션은 이 안으로 합쳤다(서브내비 '순간과 채팅'). 파형은 위에
  얇게 한 장으로 스크러버 역할만 하고, **지수 선·막대 표시는 두지 않는다** —
  줄 길이로 지수를 보이는 장치는 목록을 대시보드처럼 만들 뿐 읽는 데 도움이
  안 된다는 판단(조현빈). 지수는 목록 오른쪽 숫자 하나로만 적는다.
- **상세 페이지(2026-09-05 오후, impeccable + taste 종합 점검).** 회차 목록은
  점 축과 시각 칩의 중복을 없애고 라벨 없는 3색 막대를 대표 반응 하나로 바꿨다.
  순간 목록은 홈의 트랙리스트와 같은 열 구성이고 고른 줄 안에 재생 버튼이
  붙는다(고르는 곳 = 실행하는 곳). 파형은 상자 없이 둔다. 대표 채팅은 회색 카드
  6장이 아니라 **채팅 로그 패널**이다 — 이 제품의 채팅은 넷플릭스 위 실시간
  채팅이므로 그 모습대로 시각·닉네임·본문이 한 줄씩 흐른다. 왼쪽에 이 패널이
  무엇인지와 확장 설치 경로를 둔다.
- 모바일 순위는 6칸까지만 펼치고 '더 보기'로 접는다. 서브내비는 스크롤 위치를
  따라간다. `shot.mjs` 는 캡처 전 smooth 스크롤을 끈다(헤더가 중간에 찍히던 원인).

## 고칠 때 알아 둘 것

- **파형에는 위계가 있다.** 큰 파형은 화면당 한 장뿐이고(홈=빌보드,
  상세=순간 히트맵) 나머지는 낮은 축이거나 점이다. 카드마다 파형을 넣으면
  정보가 아니라 배경 무늬가 된다 — 실제로 한 번 그렇게 만들었다가 걷어냈다.
- **파형은 시드 고정 난수로 그린다.** `waveform()` 의 `sigma` 는 봉우리 폭이고
  막대 두세 칸이어야 순간이 분리돼 보인다. 이보다 넓히면 봉우리가 겹쳐 하나의
  오르막으로 뭉개진다(개편 중 실제로 그렇게 나왔던 값이 있다).
- **스크롤 진입 연출에는 안전망이 있다.** `useRevealed()` 는 진입 신호와 별개로
  1.2초 뒤 무조건 보이게 한다. IntersectionObserver 가 발화하지 않으면 그
  콘텐츠가 영원히 안 보이기 때문이다 — 연출이 생략되는 편이 화면이 비는 것보다
  낫다. 이 타임아웃을 지우지 말 것.
- **가로 넘침은 `overflow-x: clip` 으로 막는다.** `hidden` 이 아니라 `clip` 인
  이유는 `hidden` 이 스크롤 컨테이너를 만들어 sticky 헤더를 망가뜨리기 때문이다.
- **모서리 값은 4단 고정**(18 / 14 / 10 / 8px, `tokens.css` 와 동일). 다른 값을
  섞지 않는다.
- **홈과 상세는 문법이 다르다.** 홈은 포스터 격자와 가로 레일이 지배하고,
  상세는 표에 가까운 세로 목록이 지배한다. 회차 목록은 상세에만, 가로 카드
  레일은 홈에만 둔다.
- **섹션 여백은 세로 36px, 좌우 48px, 섹션 제목은 19px.** `SEC` 상수와
  `SectionHead` 에 묶여 있다. 이 눈금이 이 화면을 제품 화면으로 만든다.
- **가로 레일에는 `scroll-pl` 을 함께 준다.** `snap-start` 만 두면 브라우저가
  첫 항목을 컨테이너 시작선에 맞추느라 좌측 거터만큼 스크롤을 당겨, 첫 카드가
  화면 끝에 붙어 버린다.
- **포스터 자리의 여백은 `padding` 이 아니라 `inset` 으로 준다.** 퍼센트
  padding 은 자기 너비가 아니라 부모의 너비를 기준으로 계산되므로, 같은
  컴포넌트를 넓은 부모(빌보드) 안에 놓으면 패딩이 타일보다 커져 내용이
  사라진다. 퍼센트 `inset` 은 자기 자신을 기준으로 하므로 어디에 놓든 같다.
- **포스터 제목만 `word-break: normal` 이다.** 본문 전역은 어절 단위
  줄바꿈(`keep-all`)인데, "흑백요리사"처럼 공백 없는 한 어절이 타일보다 길면
  줄이 바뀌지 않아 그대로 잘려 나간다.
- **본문 글꼴은 시스템 스택이다.** 레포 규칙이 "외부 리소스 0" 이라 웹폰트를
  링크하지 않는다. `tokens.css` 의 스택(Pretendard → Apple SD Gothic Neo →
  Noto Sans KR)을 그대로 쓴다.
- **이미지 주소는 `base + size + poster_path` 세 조각으로 조립한다.**
  `data.ts`가 `posterPath`만 저장하고 `posterUrl()`이 합친다. 시안은 base와
  size를 상수로 박아 뒀지만, **서버 구현은 기동 시 `/configuration`을 받아
  캐시해야 한다** — TMDB가 크기 목록을 바꿀 수 있다.
- **`POSTERS`의 `status`를 지우지 말 것.** `provisional`은 "포스터는 보여 주되
  사람이 확인해야 한다"는 뜻이다. 화면은 둘을 구분해 그리지 않는다 — 확신이
  없다고 자리를 비우면 그게 더 나쁘기 때문이다.
- **포스터는 `image.tmdb.org`를 참조한다.** 그래서 `preview.html`을 네트워크 없이
  열면 포스터 자리가 활자 판으로 나온다. 레포의 "외부 리소스 0" 규칙과 상충하는
  지점이라 팀 판단이 필요하다. `PosterSlot`의 활자 판을 지우지 말 것 — 오프라인,
  이미지 로드 실패, TMDB 매칭 실패(현재 `두 발로 티키타카`) 셋을 모두 이게 받는다.
- **TMDB 출처 표시는 약관 §3이 요구하는 의무다.** 푸터의 영문 문구는 약관에
  지정된 원문이므로 임의로 고쳐 쓰지 않는다. 그리고 **무료 라이선스는 비상업
  전용**이라 수익모델을 붙이는 시점에 유료 서면계약이 필요하다.
- **포스터 비율은 2:3이 아니다.** TMDB 포스터는 500×700~750으로 제각각이라
  `object-fit: cover`로 채운다. 비율을 맞추려 늘리지 말 것.
- **포스터 아래 제목 줄을 지우지 말 것.** `PosterSlot`은 `aria-hidden`이라
  제목 줄이 없으면 스크린리더에 회차와 지수만 남고, 환승연애처럼 포스터에
  제목이 또렷하지 않은 작품도 있다. 한 번 지웠다가 되살렸다.
- **작품명, 채팅, 수치는 전부 예시다.** 실제로는 서버 데이터가 들어간다.

## 이 시안이 선 결정들 (개편 전부터 유지)

- **단위는 작품 → 회차 → 순간.** 한 회차 안에서도 반응이 몰린 지점이 여럿이므로
  순간을 최소 단위로 둔다(2026-09-02 조현빈 결정). 순간의 경계는 히트맵 피크
  탐지로 잡고, 순간의 이름은 LLM 이 그 구간의 **채팅만 읽고** 만든다.
- **회차 썸네일을 쓰지 않는다.** 확보가 어렵다는 판단(2026-09-03 조현빈).
- **포스터는 TMDB에서 받고, 넷플릭스에서는 꺼내지 않는다** (2026-09-04 조현빈
  결정으로 종전의 '작품 이미지 미사용'을 대체). 금지는 이미지라는 대상이 아니라
  **넷플릭스에서 추출하는 경로**에 걸려 있다는 것이 규칙 문서 개정의 요지다
  (`docs/legal-compliance-dev-rules.md` B1·B2·B6 + 'B 보충'). 큐레이션 홈은
  사용자가 열지 않은 작품 30여 개의 포스터가 필요해 B3(선수집 금지)상 넷플릭스로는
  애초에 채울 수 없었고, 배포처 경유가 유일한 경로다.
- **절대 수치를 노출하지 않는다.** 순위와 상대 강도(리플릭스 지수 0~100)만
  쓴다 — 랜딩(HP-87)이 "과장 방지를 위해 누적 수치 대신 순위만"으로 정한 선례를
  따른다. 예외는 "지금 N명"(라이브 인원)으로, 실제로 있는 사람 수라 과장이 아니다.
- **개인화, 별점, 협업 필터링 없음**(2026-07-14 팀 결정). 모두에게 같은 순위가
  보인다.
- **데이터 없는 회차를 지어내지 않는다.** 상세의 회차별 분포에서 11~14화는
  점선 자리로 남고, 그 아래 한 줄로 이유를 밝힌다.
